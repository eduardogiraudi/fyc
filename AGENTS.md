# AGENTS.md

fuckyourcli (fyc) is a Go CLI coding agent. Single Go module `fuckyourcli`, Go 1.25.

## Build & test
- The sandbox masks `.git`: always pass `-buildvcs=false` to Go commands.
  The `sh` tool injects it automatically; use `GOFLAGS=-buildvcs=false go doc ...` for documentation (go doc does not accept the flag directly), and add it yourself in editor and CI runs.
- Build: `go build -buildvcs=false ./...`
- Test: `go test -buildvcs=false ./...`
- Vet: `go vet -buildvcs=false ./...`
- Fallback extractor (no cgo): `CGO_ENABLED=0 go test -buildvcs=false ./tools/`

## Layout
- `main.go`, `helpers.go`, `globals.go`, `slash.go`, `session*.go` — CLI/TUI core (package main)
- `config/` — persisted configuration (`config.json`, schema-versioned; migrations in `persistence.go`)
- `config/secrets.go` — secret placeholders (`${VAR}` / `${VAR:-default}`) and the `auth.json` store: resolved at load, secrets migrated out of `config.json` on save; also drops the defensive `.gitignore`/`.fycignore` into the config dir
- `tools/` — tool implementations and filesystem scanners (ignore, skills, agentsmd)
- `crawl/` — HTTP-first search/extraction with browser fallback. Playwright URL routes do not intercept redirect hops: keep the browser's validating proxy and DNS-pinned HTTP dialing when changing network code. A shared fetch retains context values but is cancelled only when its last subscriber leaves.
- `reasoning/` — provider-independent thinking intent plus per-transport wire translation (no I/O; see `reasoning/intent.go` for the model)
- `models/` — models.dev catalog, a standalone JSON file at `store.ConfigDir()/models.json` (never embedded; refresh with `./update_catalog.sh` or `fuckyourcli models update`); informational, consumed by `/reasoning`
- `codexversion/` — upstream Codex compatibility version, not fyc's release version; `VERSION` is embedded for offline/plain builds and refreshed before release tags. Build-time HTTP resolution is separate from Go compilation; never require Node or an installed Codex.
- `providers/`, `mcp/`, `ui/`, `lsp/`, `modes/`, `store/`, `types/`, `agui/`

## Conventions
- AGENTS.md: add only guidance that is genuinely useful across tasks (non-obvious invariants, build quirks, layout); never task-type-scoped instructions or things discoverable from the code.
- Comments in English, kept minimal (explain WHY, not WHAT).
- Chat rendering: the inline REPL is the default and prints completed output into the terminal scrollback with `tea.Println`. With `alt_screen` (`config.AltScreen`) the same `chatModel` runs in the alternate screen, which has no scrollback: `printCmd` appends the clamped block to the shared `transcriptState` (a pointer, because the model is copied by value) and `View` must return a frame of exactly the terminal height with the input on the last row. Mouse reporting (`tea.WithMouseAllMotion`) is part of that mode: without it the terminal turns a wheel turn into arrow keys and the input walks its history (and there is no hover), so `tea.MouseMsg` handles `MouseButtonWheelUp/Down` and never reaches the input; `ReleaseTerminal` turns reporting off and `RestoreTerminal` never turns it back on, which is why `SetPromptMouse`/`ResumeExternalPrompt` re-send `tea.EnableMouseAllMotion`. Nothing may be printed to stdout before the program starts in that mode — main routes the start-up notices through `emit` and the resumed conversation through `ui.SetPreProgramBlockSink` into the transcript seed — and nested prompts release the terminal, so their own plain stdout output is only visible after quitting.
- Clickable frame parts (the `[Mode: …]` badge, the "N rows below" hint): their geometry is recorded from the rows `altScreenView` actually returned, never recomputed, so a click can only match what is on screen — and a press on one must not start a text selection. The badge label is split out of the already-rendered status line (`ui.SplitModeSegment`) because a styled segment nested under another style resets its own background mid-label; `ui.HoverButton` may only change colours, never a column, and only the text between the brackets is clickable, or the target slides out from under the pointer. Hover is the pointer position from all-motion reporting, cleared by `dropStaleHover` once the part leaves the frame.
- Confirmations and menus are hosted, not re-implemented: when `ui.EnableInAppPrompts` installed the running chat (alt-screen mode only), `ui.runInApp` sends the real model (`ui.SelectorModel`, `ui.MultiSelectModel`, the settings screens, `ui.textPromptModel`) through `ui.StreamModelMsg` and the chat draws it over the input row, so `/tools`, `/sessions`, `/settings` and every permission request keep the exact keys they have in the REPL. The caller blocks while the chat draws it, so `runInApp` must never be called from the program's own `Update`. The chat wraps the modal's commands (`wrapModalCmd`) because these models finish by returning `tea.Quit`: it must degrade to `modalDoneMsg`, otherwise the whole chat exits, and `modalDoneMsg`/`clipboardCopiedMsg` must stay out of the forwarding path that hands messages to the modal. In the inline REPL the same helpers still run as nested programs, whose output belongs to the scrollback; both paths must keep reading dismissal (`q`/`Esc`/`Ctrl+C`) as *deny* (or as an empty text answer), never as "pick the first row".
- Mouse selection: in alt-screen mode a left-drag selects transcript rows (`transcriptState.selAnchor/selCursor`, absolute rows, rebased when the cap trims the head) and the release copies them with `ui.CopyToClipboard` — native helper, then the CLIPBOARD selection this process owns over X11 (`ui/clipboard_x11.go`, pure Go on `jezek/xgb`), OSC 52 last, because the alternate screen has no terminal selection of its own. Column math goes through `ansi.Cut`/`ansi.StringWidth` on the stripped row, and `ui.SelectionHighlight` re-asserts reverse video after every embedded reset, or a styled fragment would end the highlight mid-row.
- Clipboard honesty: the X11 owner reads its ownership back from the server (a refused `SetSelectionOwner` must not be reported as a copy) and serves `TARGETS`/`UTF8_STRING`/`TEXT`/`COMPOUND_TEXT`, switching to ICCCM `INCR` above one request's payload — the requestor must select `PropertyChangeMask` for the chunks, and the owner lives only as long as the process. Every copy takes the selection with a *fresh* owner window (the previous one is kept one generation for pastes already in flight): compositors and clipboard managers react to the ownership moving, so rewriting the text under a stable owner leaves XWayland/mutter serving the first selection for the rest of the session. OSC 52 has no acknowledgement, so its confirmation never claims the clipboard was set, and it is reported as a failure where the terminal is known to drop it (VTE: `VTE_VERSION`, i.e. GNOME Terminal, Terminator, Tilix, xfce4-terminal).
- Session resume/switch replays the stored conversation as completed output: already-rendered blocks go through `ui.StreamPrintMsg` / `PrintBlock`, never through the markdown stream renderer (it would re-wrap and re-highlight them). Tool calls are replayed through `ui.FormatToolOutput` with `ui.ToolOutputRows` (the same constant the live chat uses), pairing each result with its call by id and falling back to the tool name for sessions without ids, so a resumed chat looks like the live one.
- Changing the `config.json` shape: bump `config.CurrentSchemaVersion` and add a migration in `config/persistence.go`.
- `store.LoadVersioned` decodes into a fresh value; pre-seeding its destination cannot supply defaults for missing JSON fields. Use document-level `UnmarshalJSON` for defaults that must also apply to current-schema files.
- Secrets/tokens: never store a value in `config.json`; keep a `${VAR}` placeholder and the value in `auth.json` (resolution order: `auth.json` then env). Add new secret fields to `config/secrets.go` (capture/expand/collapse), not to the read sites. When `auth.json` is unreadable, the collapse runs in `frozen` mode: keep the on-disk expressions, write nothing to the store (never drop an unresolved `${VAR}` or emit a placeholder whose value was not stored).
- Thinking/reasoning: user intent lives in `config.Reasoning` (see `config/reasoning.go`), providers translate it via `reasoning.Lookup`/`Translate`; never hard-code a provider's reasoning fields in a provider file.
- Anchored filesystem operations acquire `opMu` before the state `mu`; never hold `opMu` during a permission prompt (HITL can release the global tool mutex). Validate exact disk bytes before preview and again before writing. An external change is reconciled (Myers) rather than rejected wholesale, but never silently: a patch targeting a changed line, a line bordering a change, or a range covering lines the model has not been shown fails once with the current lines and their new anchors, and nothing is written. A change that only affects line endings or the final newline still drops the cache and requires an explicit `get_anchors`. Never print or accept anchors by guessing their shape: Anchors are shown and accepted as id + 2 check characters (`anchorToken`, e.g. `k7fwd`); maps stay keyed by the bare id and every entry point goes through `splitAnchorToken`, so a token with a wrong or missing check is refused before any lookup. `stripKnownAnchors` only removes `token§` prefixes whose id this file issued and whose check matches, because `§` can appear in source. After a successful patch `CommitEdit` maps anchors by position: lines outside the patched range always keep their anchor and Myers runs only inside the range, so identical neighbouring lines (`}`, blank lines) never swap anchors.
- `CHANGELOG.md` is updated automatically by the CI workflow. Do not edit it manually unless the user explicitly requests a changelog change.
- Release notes have a single source of truth: the reviewed, dated version section in `CHANGELOG.md`. Release CI extracts it with `cmd/release-notes`; `changelog.disable` in GoReleaser also discards explicit `--release-notes` files, so it must stay unset. Commits can contain multiple typed entries in their body: preserve them when changing commit/release tooling, and scope breaking-change footers to their entry.
- Conversation logging is context-scoped: preserve the turn/run context through provider and tool calls so resumed chats, subagents and compaction stay correlated. Debug dumps are opt-in and must never include opaque reasoning replay state or provider error text.
- Logger root locking queues in-process writers before starting the inter-process timeout; release both locks together and never hold them across provider calls.
- Provider streams use a request-scoped inactivity budget, renewed by response body bytes (not HTTP/2 pings). Keep the parent turn context separate so an idle timeout is reported as an error, not mistaken for a user interrupt. A sampling request that fails before producing any visible output (provider idle, connection dropped mid-response) is resent up to `providers.MaxStreamResends` by the `providers.WithStreamResend` decorator, which wraps the sink to detect output: the shared chat loop and `subagentStream` both apply it, and it must stay *outside* `WithLogging` so each attempt is logged. History is untouched on failure and no tool has run, so nothing can be duplicated; failures `doWithRetry` already exhausted are never resent again. A provider reader must tag in-band overload/internal errors and a stream cut before its terminal event with `transientStream(...)` (`providers.ErrStreamTransient`, message unchanged) so the resend recognises them; request/auth errors stay untagged. `Retry-After` waits above `maxRetryAfter` and `insufficient_quota` 429s are returned to the caller, never waited out. Once output is visible (text, reasoning, a diff-craft preview or tool output) the stream is partially consumed and is never replayed — the TUI commits streamed text as completed output, AG-UI already delivered it: surface the error and offer `/retry`, which starts a fresh sampling request from unchanged conversation history, never re-executes completed tools, and retains the failed turn's mode restrictions; settings changes may update system instructions but conversation rewrites invalidate the runtime checkpoint. Retry mode restoration must preserve persistent versus one-shot bookkeeping; after compaction, mode instructions must have a single carrier (history or transport), including in subsequent retry checkpoints. Clean EOF alone does not prove completion: require a protocol terminal signal except for valid, non-empty text-only Chat Completions streams (compatibility fallback; never tool calls). Token-limit terminal events are not transport errors, even when only reasoning was emitted. Distinguish explicit safety blocks from transport truncation.
- Duplicate tool results are pruned only in the compaction transcript (superseded snapshot calls become a note): never in the live history or the persisted session, and a tool result must always keep its role/name/`tool_call_id` pairing. Assign missing call IDs to the whole batch before executing it, including Gemini: transports may omit IDs on the wire, never in canonical history.
- The compaction trigger uses the provider's own prompt-token count (`types.StreamResult.ContextTokens`, extended by the local estimate of the messages appended since the request); the local estimate is only the fallback and the sanity check for an implausible figure (see `contextTokens` in `tokens.go`). Each provider normalises the count at parse time because the APIs report it differently: Anthropic's `input_tokens` is only the uncached tail (`input + cache_creation + cache_read` is the prompt), while OpenAI-compatible `prompt_tokens`, Responses/Codex `input_tokens` and Gemini `promptTokenCount` already include the cached part.
- The compaction model (`compaction_model`) is resolved from `config.Get()` on every attempt and never written back: the fallback policy, `/models` switching and concurrent sessions must not mutate the active provider. A compactor that no longer resolves is an API-level failure, handled by the same policy as a 404. A provider idle timeout arrives as a wrapped `context.DeadlineExceeded` with the turn context intact: it is an error and must fall back, never be mistaken for a user interrupt. When the parent turn context is cancelled during either attempt, its error takes precedence over provider failures so callers retain the cancellation identity.
